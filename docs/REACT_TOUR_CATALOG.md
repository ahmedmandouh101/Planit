# React — عرض الرحلات من API

الخطوة الثانية تستبدل بيانات الكارت التعليمية برحلات من الباك إند.
بيانات Demo الموجودة في قاعدة البيانات تظل تجريبية وتظهر بعلامتها.

## التشغيل

شغّل قاعدة البيانات والباك إند حسب `LOCAL_DEVELOPMENT.md`، ثم في terminal آخر:

```sh
npm --prefix client ci
npm run dev:client
```

افتح `http://127.0.0.1:5173/react/`. الباك إند مطلوب على port 3000؛ لو غيرته
عدّل العناوين في `client/vite.config.js`. Vite يمرر طلبات `/api` والصور إلى
الباك إند أثناء التطوير. بعد البناء، Express يقدم React والـAPI من نفس العنوان.

```sh
npm run test:client
npm run build:client
```

## تتبع البيانات خطوة بخطوة

1. `App` يظهر حالة تحميل في البداية.
2. `useEffect` يبدأ طلب الرحلات بواسطة `fetchTours`.
3. `fetch` يطلب `/api/v1/tours` ثم يحول الاستجابة إلى JSON.
4. الـAPI الحالي يرجع القائمة داخل `data.data`؛ نتحقق من شكلها قبل عرضها.
5. `setTours` يخزن القائمة في State وReact يعيد حساب الواجهة.
6. `tours.map` يحول كل رحلة إلى `TourCard`، و`key` يعرّف الكارت بمعرف الرحلة الثابت.

## لماذا useEffect؟

طلب الشبكة تعامل مع نظام خارج React؛ لا نكتبه مباشرة في جسم المكوّن، لأن
جسم المكوّن يعمل كل مرة يعاد فيها العرض.

قائمة `[page, attempt]` تعني إعادة تشغيل الطلب عند تغيير صفحة البيانات أو
الضغط على المحاولة مرة أخرى. `attempt` عداد لإعادة نفس الطلب؛ لا يغير الصفحة.

دالة `cleanup` تستدعي `controller.abort()` لإلغاء الطلب السابق. نتحقق أيضًا
من إلغاء الطلب قبل تخزين نتيجته حتى لا تستبدل نتيجة قديمة البيانات الحالية.
يوجد حد انتظار 10 ثوانٍ يتحول بعده الطلب إلى حالة خطأ قابلة للمحاولة مرة أخرى.

## الحالات التي نعرضها

- `loading`: رسالة تحميل، وزر تحميل المزيد غير ظاهر أثناء الطلب.
- `success` وقائمة فارغة: رسالة عدم وجود رحلات، بدون بيانات تعليمية بديلة.
- `success` وقائمة بها بيانات: كروت الرحلات.
- `error`: رسالة واضحة وزر لإعادة المحاولة.

نطلب 12 رحلة في كل مرة، بترتيب السعر ثم المعرف لثبات ترتيب الأسعار المتساوية.
الـAPI لا يرجع إجمالي عدد النتائج؛ لو الصفحة فيها 12 نتيجة نتيح تحميل المزيد.
لو آخر صفحة كانت بالضبط 12 رحلة، قد يحتاج المستخدم ضغطة أخيرة تنتهي بنتيجة فارغة.
عند فشل صفحة لاحقة نحتفظ بالكروت السابقة ونعيد طلب نفس الصفحة، ونمنع تكرار المعرفات.

## الاختبارات

اختبارات React تحاكي استجابات الشبكة لتفحص التحميل والبيانات الفارغة، وفشل الطلب
وإعادته، والاستجابات غير الصالحة، وتحميل صفحة إضافية، وإلغاء الطلبات القديمة،
وزر التفاصيل، وفشل تحميل صورة. هي لا تثبت اتصال قاعدة البيانات الفعلية.
