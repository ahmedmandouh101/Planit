# React — الخطوة الأولى

بدأنا تحويل الواجهة تدريجيًا. الواجهة الحالية تظل متاحة، وصفحة React الجديدة
على `/react/`. الكارت الحالي بيانات تعليمية فقط، ولا ينشئ حجزًا.

## التشغيل

استخدم Node.js 22.12 أو أحدث ضمن إصدار 22.

```sh
npm --prefix client ci
npm run dev:client
```

افتح `http://127.0.0.1:5173/react/`. الصفحة التعليمية لا تحتاج قاعدة بيانات.
لبناء نسخة يقدمها Express:

```sh
npm run build:client
npm start
```

بعد تشغيل الباك إند بإعداداته وخدماته المعتادة، افتح `/react/` على نفس عنوانه.
ملفات البناء في `client/dist` مولدة ولا نرفعها إلى Git؛ يجب بناؤها أثناء النشر.

## افهم مسار التنفيذ

1. `client/index.html` يحتوي على `div` اسمه `root` ويحمّل ملف البداية.
2. `client/src/main.jsx` يطلب من React عرض `App` داخل `root`.
3. `client/src/App.jsx` يجمع الصفحة ويرسل بيانات الرحلة إلى `TourCard`.
4. `client/src/components/TourCard.jsx` يعرض الكارت ويتعامل مع زر التفاصيل.

**Component** دالة اسمها يبدأ بحرف كبير وترجع وصفًا للواجهة بـJSX.
JSX يشبه HTML، لكن الأقواس `{}` تسمح باستخدام قيم JavaScript داخله.

**Props** بيانات يستقبلها المكوّن من المكوّن الأب. في `<TourCard tour={sampleTour} />`
يرسل `App` الرحلة إلى `TourCard`. نقرأ البيانات داخل الكارت ولا نعدّلها.

**State** ذاكرة للمكوّن. `useState(false)` تبدأ التفاصيل مغلقة، وترجع القيمة
الحالية ودالة تغييرها. الضغط يستدعي `setIsExpanded` بقيمة عكس السابقة،
فيعيد React حساب الواجهة ويحدّث الجزء المتغير. لا نحتاج `querySelector`
لتغيير نص الزر يدويًا.

`useId` يولد معرفًا يربط الزر بالتفاصيل لتقنيات المساعدة حتى لو كررنا الكارت.
`StrictMode` يساعد على اكتشاف مشكلات أثناء التطوير.

## تمرين صغير

غيّر اسم الرحلة في `sampleTour`، ثم لاحظ تحديث الصفحة. افتح وأغلق التفاصيل،
واقـرأ تعبير `isExpanded ? 'Hide details' : 'Show details'`: يختار النص حسب الحالة.

## الفيتشر التالية

عرض قائمة رحلات حقيقية من API، مع حالات التحميل والخطأ والنتائج الفارغة.
وقتها نتعلم `useEffect` و`fetch` و`map` بدل إضافة مفاهيم كثيرة في أول خطوة.
